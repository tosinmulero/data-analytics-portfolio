RailFlow ML Data Platform

End-to-end UK rail data and machine-learning platform spanning medallion data engineering, dbt analytics, Airflow orchestration, MLflow model governance, secure FastAPI serving, Docker, GitHub Actions, Terraform and AWS ECS/Fargate.

The problem

How can publicly sourced station-usage records move from raw files through verified analytics and machine learning to a secure, reproducible cloud API?

Data & provenance

ORR station-usage release: 2,595 source/Bronze records, of which 2,593 are represented in validated Silver/Gold outputs.

Technical approach

  1. Process raw, Bronze, Silver and Gold layers with deduplication and schema checks.
  2. Build dbt marts and a deterministic machine-learning feature dataset.
  3. Manage data and model pipelines with Airflow and track candidate models in MLflow.
  4. Validate serving artefacts, containerise FastAPI, and deploy AWS ECS/Fargate through Terraform and GitHub Actions.

Documented findings

  • 2,593 curated station records are validated.
  • The repository reports 29 dbt build passes and 38 pytest passes.
  • Infrastructure deployment evidence records 25 Terraform-managed AWS resources.

Decision relevance

Demonstrates reproducibility, security boundaries, model artefact governance, orchestration and deployment beyond notebook experimentation.

Limitations & responsible interpretation

The single annual release supports cross-sectional estimation, not a reliable time-series forecast. Cloud resources were intentionally made ephemeral for cost control.

AWS ECS/Fargate deployment was successfully verified end-to-end. The portfolio environment is intentionally ephemeral so cloud infrastructure can be destroyed after validation to control recurring cost.
